# 開発範囲（SOW）

## 目的
MacでJR-200用ゲームを作成し、CJR生成・検証・実行確認・公開まで再現できる環境を作る。
エミュレータの開発・CIとは分離し、ゲーム単位でビルドと配布を管理する。

## 範囲と成果物

| 項目 | 成果物・受入の基準 |
| --- | --- |
| 外部ツール | jrasmの固定版・導入確認・実行ファイル指定。改変版の配布はしない |
| 開発ルール | 命令・メモリ・スタック・割込み・画面・入力・音声・BASIC復帰の制約を一次資料と実装で確認 |
| SDK | 必要最小限の画面・入力・音声・待機処理とテンプレート。実装した機能ごとにサンプルと試験 |
| 開発操作 | 新規作成、ゲーム単体build/test/run/package。エミュレータのソースビルドを暗黙に要求しない |
| 配布 | CJR、必要時のみWAV、バージョン・ロード／実行手順・ライセンスを含む作品別パッケージ |
| CI | 文書変更のゲームビルド0件、単一ゲーム変更は当該ゲームのみ、共通変更は逆依存先のみ |
| Wiki | 作品情報から一覧と個別ページを生成。検証済みで公開指定した版だけを案内 |

専用IDE、アセンブラ／リンカーの独自開発、セミグラ変換、フォント編集、ROM配布は対象外。
C++→WASMはエミュレータ側の実装方式であり、このSDKがJR-200向けC++コンパイラを提供する意味ではない。

## リポジトリの境界

本リポジトリは `rules/`、`sdk/`、`templates/`、`samples/`、`games/` と開発支援を担当する。
未実装ディレクトリを空の機能として作らず、ソース追加時に必要なディレクトリを作る。
エミュレータ・CPU・Web UI・カセット／WAVコアのコピーを持たない。
実行試験は別配布の固定ランナーを使用し、version・digest・呼び出し契約を固定する。
ランナー取得不能時にエミュレータを無断で再ビルドしない。必要な試験を実行できない場合は未検証として停止する。

## ゲームの単位

各 `games/<id>/` に `src/`、組込み用 `assets/`、`tests/`、`Makefile`、`build.json`、
紹介用 `README.md`・`game.json`・`media/` を持たせる計画とする。
`build.json` はロード／エントリ・メモリ条件・依存・変換条件等、`game.json` は公開用メタデータを担当する。
テスト・起動条件を紹介用メタデータに隠して、説明文変更として検証を省略しない。

`ci/targets.json` はビルド／テスト／文書入力とターゲット間依存を宣言する。
ソースのincludeやアセット変換依存はビルダーの依存ファイルと突合し、宣言漏れを検査する。
同じPNGでも `assets/` の入力画像はビルド対象、`media/` の紹介画像はWiki対象として区別する。

## Wikiと公開

正本は `game.json` とREADME、配布物は作品別の固定バージョンとする。Wikiはその生成表示である。
一覧にはジャンル・タイトル、作品ページには遊び方・画面例・ロード／実行手順・ダウンロード・検証範囲を載せる。
「遊ぶ」リンクはエミュレータ側の対応を確認して導入し、未対応時はCJR手動読込みを案内する。

公開処理は検査と分離し、mainの検証済み版について明示的な公開指定がある場合だけ実行する。
作品Aの公開で作品Bの生成物を作り直さない。説明文だけの変更では既存の検証済み配布物を参照する。
生成対象のWikiページのみを同期し、手書きページを上書きしない。差分0ならpushしない。
Wikiの初期化と必要な書込み権限は同期実装時に確認する。資格情報はコードやログへ入れない。

privateリポジトリのWikiは一般公開カタログにならない。公開時のvisibility変更は別途承認して実施する。
初期設定ではWikiへのpush・Release作成・public化は行わない。

## 完了の判定

最初のゲーム1本で作成→ビルド→自動試験→エミュレータ→配布→Wikiを通す。
ROMなし合成試験、実ROMでのエミュレータ試験、実機試験は別に記録する。
CJR/WAV自己往復だけで実機動作保証としない。
作業順序と受入条件はIssuesを正本とし、同じ計画を別文書へ複写しない。
