# DICE RELIC

3個のダイスを振り、出目を攻撃・防御・回復へ割り当てて、8体の守護者と最後の王を倒すゲームです。
勝利ごとに工房で金貨を使い、ダイスの面を作り替えます。
JR100devの`DICE RELIC 1.7.1`（`games/dice_relic`）を仕様として、JR-200向けにM6800アセンブリで作り直しました。
上流はJR-100向けの手書きアセンブリで、戦闘・価格・乱数は上流の`model.py`（Pythonの独立モデル）と一致します。
この版の`tests/model.py`はその規則をそのまま持ち、上流`src/main.asm`の選択操作、次のダイスへの自動移動、
工房とそのメニューを加えた検証用モデルです。9体の守護者は上流の`enemies.json`です。

## 目的と勝敗

- 毎ターン3個のダイスを振ります。`A`/`D`でダイス、`W`/`S`で割当先（ATTACK／GUARD／HEAL／REROLL）を選び、`RETURN`で使います。
- ATTACKは出目の値だけ敵のHPを減らし、GUARDは同じ値の防御、HEALは同じ値のHP回復です（上限42）。各ダイスは1ターンに1回だけ使えます。
- REROLLは未使用のダイスを1ターンに1回だけ振り直します。使用済みのダイスや2回目の振り直しは`NOT POSSIBLE`で断られます。
- 3個すべてを使うと敵が攻撃します。攻撃は4ターンごとに2増え（左の`NEXT`に今回の値）、防御で軽減した残りがHPに入り、防御は消えます。
- 敵を倒すとそのターンの反撃はなく、HPが2回復して金貨を3枚得ます。王（9体目）を倒すと成功、HPが0になると失敗です。
- 工房では`A`/`D`でダイス、`W`/`S`で6面のどれかを選び、`RETURN`でメニューを開きます。
  FORGE（金貨3、選んだ面を+2、上限9）、HEAL（金貨2、HP+6、満タンなら不可）、NEXT（次の戦闘）、BACK。作り替えた面は以後の戦闘で使われます。

## 操作

| 場面 | key | 動作 |
| --- | --- | --- |
| タイトル | `RETURN` | 始める |
| タイトル | そのほか | 説明 |
| 戦闘 | `A` / `D` | ダイスを選ぶ |
| 戦闘 | `W` / `S` | 割当先を選ぶ |
| 戦闘 | `RETURN` | 使う |
| 工房 | `A` / `D` / `W` / `S` | ダイス／面を選ぶ |
| 工房 | `RETURN` | メニュー |
| 工房のメニュー | `A` / `D` | FORGE／HEAL／NEXT／BACKを選ぶ |
| 工房のメニュー | `RETURN` / `SPACE` | 決定／閉じる |
| 成功後 | `RETURN` | 結果画面、もう一度でタイトル |
| 失敗後 | `RETURN` | やり直すか確認（`D`でYES） |
| どこでも | `ESC` / `CTRL+C` | ゲームを終えてBASICへ戻る |

## 最初の目標と序盤のコツ

- 最初の敵DUST IMPはHP14、攻撃3です。大きな目を攻撃に、敵の攻撃が強いターン（`NEXT`が増えるとき）は防御にも回します。
- 工房では小さい面から作り替えると、平均の出目が上がります。

| もの | 色 | 形 |

| 守護者 | 敵ごとに変わる色（被弾で赤く点滅） | 立像（王は冠） |
| 主人公（YOU） | 緑（被弾で赤く点滅） | 人、攻撃で踏み込む |

## 乱数

上流は新しいゲームの開始時にタイマー（`TICK OR 1`）を乱数の種にします。この版は、`RETURN`を押したときのタイトル曲の位置を種にします（状態の`seed`、`$464A`）。
乱数の更新（左へ1bit、桁あふれで0x1DとXOR）と出目（乱数を6で割った余りの面）は上流と同じです。

## 起動

1. CJRを通常の`MLOAD`で読み込みます。
2. BASICから`A=USR($1000)`を実行します。
3. 終了後はBASICへ戻り、画面・ユーザー文字・文字RAM・キー制御ポートは起動前の状態に戻り、3つの音源は止まります。

標準のRAM構成で、ロード先は`$1000-$2FFF`、作業領域は`$3000-$4FFF`（専用stackを含む）です。

## 開発と検証

ターン制なので、各規則と通しの成功・失敗を固定エミュレータのキーreplayで確かめます。
`tests/expectations.json`の期待値は`tests/model.py`が計算した値で、エミュレータの出力を写したものではありません。
乱数の種はエミュレータが取った値（状態の`seed`）を読み、残りはその種からモデルが計算します。
`synthetic-nine-battles`は上流`replay.py`の方針（見えている出目とHUDから割当を選び、勝つたびに最も小さい面を鍛える）で9戦を完走します。
敗北は通常のreplayでは起こせません（すべてのダイスを回復か防御に使えば、どの守護者の攻撃にも耐えられるため）。
HPが0になる規則はモデルの試験（`tests/test_dice_relic.py`）で確かめ、失敗のジングルは固定エミュレータでは未確認です。
キーの間隔は、演出1フレームあたり4.2万cycle、振り直し1回あたり75万cycleを見込みます。
