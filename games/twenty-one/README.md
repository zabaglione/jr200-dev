# TWENTY ONE

ディーラーを相手に、7回の勝負を終えたときに持ち金12以上を目指すブラックジャックです。1面です。
JR100devの`TWENTY ONE 2.0.0`（`games/twenty_one/rules.py`）を仕様として、JR-200向けに
M6800アセンブリで作り直しました。52枚の山札のシャッフル、配り方、エースの数え方、ディーラーが17まで引く規則、
ダブル、ナチュラル21、7回の勝負と目標は上流と同じです。

## 目的と勝敗

- 持ち金10で始まり、1回の賭け金は2です。合計が21を超えない範囲でディーラーより大きければ勝ちです。
- `HIT`で1枚引き、`STAND`で勝負します。`DOUBLE`は最初の2枚で持ち金4以上のときだけ選べ、賭け金を4にして1枚だけ引いて勝負します。
- エースは1または11、絵札は10です。最初の2枚で21（ナチュラル）なら勝ったときに3増えます。引き分けは持ち金が変わりません。
- ディーラーの2枚目は勝負まで伏せられ、ディーラーは17以上になるまで引きます。
- 持ち金が2未満になると失敗（`NO COINS LEFT AT THE TABLE`）、7回終えて12未満なら失敗（`SEVEN HANDS ENDED BELOW 12`）、12以上ならクリアです。

山札の並びは卓を始めるたびに変わります。上流はJR-100のタイマー（`entropy()`）を種にしますが、JR-200版はタイトル曲の再生位置を種にします。

## 操作

| key | 動作 |
| --- | --- |
| `A` / `D`（`W` / `S`） | `HIT`・`STAND`・`DOUBLE`を選ぶ |
| `RETURN` | 決定 |
| `SPACE` | やり直し確認。初期選択はNO、`A`/`D`で選び`RETURN`で確定 |
| `ESC` / `CTRL+C` | ゲームを終えてBASICへ戻る |

札が山から飛んでくる演出、ディーラーの追加の札、勝敗の表示が終わってから次のキーを押してください。

## 最初の目標と序盤のコツ

- 12以上で引くと21を超えやすくなります。ディーラーの見えている札が弱いときは早めに止めます。
- 11や10のときの`DOUBLE`は、1回で4増やせる機会です。

## 音

| 場面 | 音 |
| --- | --- |
| タイトル | ト短調の3声のスウィング（音源F・D・Cを同時に使用、ループ） |
| 札を配る | 短い2音（音源C） |
| 勝ち | 上がる3音（音源C） |
| 負け・ダブルできない | 低いブザー（音源C） |
| 引き分け | 短い2音（音源C） |
| クリア | 3声のト長調アルペジオ |
| 失敗 | 3声の下がる音型 |

## 起動

1. CJRを通常の`MLOAD`で読み込みます。
2. BASICから`A=USR($1000)`を実行します。
3. 終了後はBASICへ戻り、画面・ユーザー文字・文字RAM・キー制御ポートは起動前の状態に戻り、3つの音源は止まります。

標準のRAM構成で、ロード先は`$1000-$2FFF`、作業領域は`$3000-$4FFF`です。

## 開発

```sh
JRASM=/absolute/path/to/jrasm make build
RUNNER_BUNDLE=/absolute/path/to/emulator/bundle make run
```

`tests/model.py`は上流`rules.py`を写したPythonモデルで、`tests/expectations.json`のRAM期待値を計算します。
エミュレータから取るのは卓の開始時の種（`origin`、`$4760`に記録）だけで、シャッフルした山札を含むほかの値はすべてモデルの予測です。
選択は、その種に対してモデルの探索（`plan()`）で求めた、7回で12以上になる手順です。全256通りの種でそのような手順があることを確認しています。
