# SIGIL DECK

手札4枚、エナジー3から始まる10戦のカードバトルです。勝つたびに3枚の報酬から1枚をデッキに加えるか休んで回復し、攻撃・防御・毒・回復を組み合わせて虚空の王を封じます。
JR100devの`SIGIL DECK 1.6.1`（`games/sigil_deck`）を仕様として、JR-200向けにM6800アセンブリで作り直しました。
上流はJR-100向けの手書きアセンブリで、規則は上流`src/main.asm`と`src/cards.asm`に従います。
この版の`tests/model.py`はそれを写した検証用モデルで、カードの計算は上流`replay.py`の`card_result`、境界と順序は上流`check_rules.py`の場面で確かめています。
24種のカード、8体の敵と10戦の順番、敵の絵（16×16）は上流の`cards.json`、`enemies.json`、`assets.py`です。

## 目的と勝敗

- HPは最大60。各ターンにエナジーが3へ戻り、空いた枠へ手札を4枚まで引きます。
- `A`/`D`でカード（右端はEND TURN）を選び、`RETURN`で使います。エナジーが足りないカードや空の枠は使えません。`SPACE`でEND TURNへ移ります。
- 使ったカードとターン終了時の残りの手札は捨て札へ。山札が尽きると捨て札を山札に戻します。EXHAUSTのカードはその戦闘から除外され、次の戦闘で戻ります。
- 敵の次の行動を`NEXT`に表示します。攻撃・防御・強攻撃（+2）の順に循環します。
- SHは防御値で、まず防御で攻撃を受け、残りがHPに入ります。自分の防御は次の自分のターンで消え、敵の防御も次の敵行動までです。
- POISONは敵の行動の前に防御を無視してダメージを与え、1ずつ減ります。WEAKは敵の攻撃を3減らし、VULは自分の攻撃を50%増やします（端数切り捨て）。
- STRは戦闘中の攻撃加算、ECHOは次の攻撃を2倍、THORNはそのターンの敵の攻撃への反撃です。
- 勝つと3枚から1枚をデッキに加えるか、RESTでHPを10回復します。どちらも追加でHPが4回復します。10戦目のVOID SOVEREIGNを倒せば成功です。
- HPが0になると失敗です（敵と同時に倒れた場合も失敗）。

## 操作

| 場面 | key | 動作 |
| --- | --- | --- |
| タイトル | `RETURN` | 始める |
| タイトル | そのほか | 説明 |
| 戦闘 | `A` / `D` | カード／END TURNを選ぶ |
| 戦闘 | `RETURN` | 使う／ターンを終える |
| 戦闘 | `SPACE` | END TURNを選ぶ |
| 戦闘 | `W` | デッキを見る（どのキーでも戻る） |
| 報酬 | `A` / `D`、`RETURN` | 3枚かRESTを選び、決定 |
| 成功後 | `RETURN` | 結果画面、もう一度でタイトル |
| 失敗後 | `RETURN` | やり直すか確認（`D`でYES） |
| どこでも | `ESC` / `CTRL+C` | ゲームを終えてBASICへ戻る |

## 最初の目標と序盤のコツ

- 最初の敵ASH WRAITHはHP18、攻撃4です。STRIKE 3枚で倒せます。`NEXT`が強攻撃のターンはWARDで受けます。
- 報酬はデッキを強くするカードを選び、HPが減っているときはRESTで回復します。

## 画面（色と記号）

| もの | 色 | 形 |
| --- | --- | --- |
| 敵 | 敵ごとの色（被弾で赤、毒で紫） | 16×16の絵を4分割の文字で8×8文字に描く |
| カード | 攻撃は赤、防御は水色、そのほかは紫の枠（エナジーが足りないと青） | 名前、コスト、剣・盾・紋章と値、EXH |
| 引いたカード | 白い枠 | 補充される手札を1枚ずつ表示 |
| 選択 | 黄 | カードの上の矢印、END TURNの前の矢印 |
| 被弾 | 白 | 敵に重なる斬撃 |
| 防御・回復 | 水色・緑 | 自分の値の横の盾と十字 |

上段は自分のHP・防御・エナジー、戦闘番号、山札（DRAW）・捨て札（USED）・除外（X）の枚数です。左右は敵の状態と自分の強化、下段は選んだカードの効果です。
使ったカードの効果（攻撃、防御、回復）、毒、敵の行動、補充される手札を、上流と同じく1段ずつ（16フレーム）見せます。

## 乱数

上流は新しい挑戦の開始時にタイマー（`TICK OR 1`）を乱数の種にします。この版は、挑戦を始めたときの曲の位置を種にします（状態の`seed`、`$5659`）。
乱数の更新（左へ1bit、桁あふれで0x1DとXOR）、引く札（山札の枚数で割った余りの位置、空いた位置へ末尾の札を移す）、報酬（24で割った余り、重複は引き直し）は上流と同じです。

## 起動

1. CJRを通常の`MLOAD`で読み込みます。
2. BASICから`A=USR($1000)`を実行します。
3. 終了後はBASICへ戻り、画面・ユーザー文字・文字RAM・キー制御ポートは起動前の状態に戻り、3つの音源は止まります。

ロード先は`$1000-$3FFF`（コードが8KBを超えるため）、作業領域は`$4000-$5FFF`（専用stackを含む）です。

## 開発と検証

ターン制なので、各規則と通しの成功・失敗を固定エミュレータのキーreplayで確かめます。
`tests/expectations.json`の期待値は`tests/model.py`が計算した値で、エミュレータの出力を写したものではありません。
乱数の種はエミュレータが取った値（状態の`seed`）を読み、残りはその種からモデルが計算します。やり直しでは新しい種を取るため、`synthetic-lost-retry`はその種も読みます。
`synthetic-ten-battles`は上流`replay.py`の方針（見えている手札とHUDだけでカードと報酬を選ぶ）で10戦を完走します（232キー）。
キーの間隔は1キー25万cycleに、演出1フレームあたり6万cycleを足します。
`src/data.inc`は`tests/make_data.py`が`tests/data.py`から生成します。
上流の方向＋1ボタンパッド操作と、プレイ中のタイトル移動の確認は、この版にはありません（`ESC`で終了します）。
