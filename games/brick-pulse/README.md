# BRICK PULSE

A／Dを押し続けてパドルを動かし、ボールで12面のブロックを崩すアクションゲームです。
各面3球、何度も当てる装甲ブロック、3面目からのドローン、6面目からの爆弾、W／S／Gのアイテムがあります。
JR100devの`BRICK PULSE 2.3.1`（`games/brick_pulse/rules.py`）を仕様として、JR-200向けに
M6800アセンブリで作り直しました。面の構成、反射、得点に当たる数値、残球、敵とアイテムの出現、
効果時間は上流と同じです。

## 目的と勝敗

- 面のブロックをすべて壊し、ドローンがいる面ではドローンも倒すと面クリアです。
- パドルの下へボールを落とすと1球減り、3球すべて失うと失敗です（`TRY AGAIN`）。
- 12面をクリアすると`ALL STAGES CLEAR - THANK YOU`で終わります。

| 要素 | 内容 |
| --- | --- |
| ブロック | 黄＝あと1回、紫＝2回、赤＝3回。模様も回数で変わる |
| ドローン | 3面目から上段を往復。当てると減り、全滅で`G`を落とす |
| 爆弾 | 6面目からドローンが落とす。パドルに当たると`JAM`（幅4、約48 tick） |
| `W` | パドルが幅10に広がる（`WIDE`） |
| `S` | ボールが半分の速さになる（`SLOW`） |
| `G` | 下に1回だけボールや爆弾を防ぐ線を張る（`GUARD`） |

アイテムはブロックを3個壊すごとに落ち、同時に落ちるのは1個だけです。

## 操作

| key | 動作 |
| --- | --- |
| `A` / `D`（押し続ける） | パドルを左右に動かす。短く押すと1歩だけ動く |
| `RETURN` | タイトルで開始、面クリア後に次の面、失敗後にやり直し確認 |
| `P`（タイトル） | 1面の自動デモを見る（`DEMO`表示） |
| `CTRL+C` | ゲームの終了処理を通してBASICへ戻る。Webエミュレータでは`CTRL+SHIFT+C`で送る |

押している間の判定はキーボードMCUの走査（BASIC ROMの入力走査と同じ手順）で読みます。
キーを離すと次のtickで止まり、ブラウザのフォーカスが外れてキーが離された場合も同じです。
ブロックに当たったときの点滅と破片の演出の間はゲームの時計が止まります。
ジョイスティックには対応していません。
Webエミュレータの`Escape`キーはJR-200の`BREAK`（NMI）です。ゲームの終了処理を通らず、
画面が復元されないため、終了操作には使わないでください。

## 最初の目標と序盤のコツ

- ボールはパドルの端で当てると斜めに、中央付近で当てると急角度で跳ね返ります。
- 最初の目標は1面（装甲なし、12個）を3球のうちにクリアすることです。
- 爆弾が落ちる面では、`G`を取っておくと爆弾を1回防げます。

## 起動

1. CJRを通常の`MLOAD`で読み込みます。
2. BASICから`A=USR($1000)`を実行します。
3. 終了後はBASICへ戻り、画面・ユーザー文字・文字RAMとキー制御ポートは起動前の状態に戻ります。

標準のRAM構成で、ロード先は`$1000-$2FFF`、作業領域は`$3000-$5FFF`（専用stackと自己試験の結果を含む）です。
上流は1 tick＝1/60秒×5でしたが、この版は1 tickが約10万cycle（固定エミュレータで約13 tick/秒）です。

## 開発と自己試験

タイトルで`T`を押すと開発用の自己試験を実行し、終わるとタイトルへ戻ります。
`tests/fixtures.py`の34件の状態から1 tickずつ進めた結果と、自動操縦で12面を最後まで遊んだ結果を
`$5000`以降のRAMへ書き出します。`tests/expectations.json`の期待値は`tests/model.py`（上流ルールの
Pythonモデル）が計算した値で、固定runnerはエミュレータ上の結果が一致しなければ失敗します。
自動操縦は全12面を計8,918 tickでクリアします。`src/fixtures.inc`は`tests/make_fixtures.py`で
`tests/fixtures.py`から生成します。

キー入力はtickとの時間関係で結果が変わるため、短押し・押し続けの試験はパドル位置だけを観測します。

| 区分 | 状態 |
| --- | --- |
| ROMなし合成実行（固定エミュレータ） | 34件のルールfixture、自動操縦での12面クリア、自動デモ、無入力での3球喪失と再挑戦、短押し・押し続け・離上、BASIC復帰を確認 |
| 所有ROM/FONTでの通常`MLOAD`/`USR` | 固定runnerで12面の自己試験、1面の自動デモ、3球喪失・再挑戦、左右の保持・離上を確認。ローカルChromiumの100%速度で起動・単発操作・`CTRL+SHIFT+C`でのBASIC復帰を確認し、終了前後のPCG・画面コード・属性・フォントの比較対象各256バイトは一致。ローカルChrome 153／Firefox 155／Playwright WebKit 26.6では100%速度の第1面で短押し・保持・離上・タブフォーカス喪失を確認し、最初の移動までそれぞれ70／77／55ms。native Safari 26.6.2では公開0.1.0の第12面で180ms短押しの未応答を発見。修正版0.1.1のCJRを通常MLOAD/USRから3回試験し、15件の押下すべて応答、最大34ms。方法と数値は[追加受入記録](https://github.com/zabaglione/jr200-dev/blob/main/docs/BRICK_PULSE_SAFARI_ACCEPTANCE.md)を参照。公開版の選択はWebカタログの版表示で確認 |
| 物理JR-200 | 未実施（キーボードMCUの走査手順は固定エミュレータの実装に基づく） |
