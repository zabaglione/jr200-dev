# TIDE BRIDGE

潮の満ち引きで沈む橋板を、行や列ごとに上げ下げして、岸から門までの道をつなぐパズルです。全3面です。
JR100devの`TIDE BRIDGE 1.6.1`（`games/tide_bridge/rules.py`）を仕様として、JR-200向けに
M6800アセンブリで作り直しました。橋板の初期配置、行・列の反転、岸から門への探索、歩く道順、30回の変更上限は上流と同じです。

## 目的と勝敗

- 6×6の水面に橋板が並びます。選んだ行または列の6マスを一度に反転させ、橋板を水面に、水面を橋板にします。
- 左下の岸（主人公の位置）から右上の門まで、上下左右に橋板がつながると、主人公が門まで歩いてクリアです。
- 1面30回まで変更できます。30回目でもつながらなければ失敗（`TRY AGAIN - RETURN TO RESTART`）です。
- 3面をクリアすると`ALL STAGES CLEAR - THANK YOU`で終わります。

## 操作

| key | 動作 |
| --- | --- |
| `W` / `S` | 対象の行・列を選ぶ（6本で循環） |
| `A` / `D` | 行と列を切り替える |
| `RETURN` | 選んだ行・列を反転する |
| `SPACE` | この面のやり直し確認。初期選択はNO、`A`/`D`で選び`RETURN`で確定 |
| `ESC` / `CTRL+C` | ゲームを終えてBASICへ戻る |

道がつながると、主人公が進行方向を向き、マスの中間を通って門まで歩き、到着後に2回跳ねます。演出が終わってから次のキーを押してください。

## 最初の目標と序盤のコツ

- 反転は同じ行・列を2回行うと元に戻ります。順番は結果に影響しません。
- 岸のある下段と門のある上段を先に見て、縦の通り道になる列を決めます。
- 各面は4回の変更で解けます。

## 画面（色と記号）

| もの | 色 | 形 |
| --- | --- | --- |
| 水面 | 青の地に水色 | 波 |
| 橋板 | 青の地に黄 | 板 |
| 選んだ行・列 | 紫の地（水面は水色、橋板は黄） | 両端に紫の`>` `<`（行）または`V` `^`（列） |
| 門 | 青の地に緑 | 門 |
| 主人公 | 青の地に白 | 上下左右の向き、両手を上げる姿、跳ねる姿 |
| 変更回数 | 白。25回以上で赤 | `CHANGES nn /30` |
| 到着 | 黄 | `ARRIVED!`、`HOORAY!` |

## 音

| 場面 | 音 |
| --- | --- |
| タイトル | ニ長調の3声の舟歌（音源F・D・Cを同時に使用、ループ） |
| 反転・到着の喜び | 下がる3音（音源C） |
| 歩く | 短い音（音源C） |
| クリア | 3声のニ長調アルペジオ |
| 失敗 | 3声の下がる音型 |

## 起動

1. CJRを通常の`MLOAD`で読み込みます。
2. BASICから`A=USR($1000)`を実行します。
3. 終了後はBASICへ戻り、画面・ユーザー文字・文字RAM・キー制御ポートは起動前の状態に戻り、3つの音源は止まります。

標準のRAM構成で、ロード先は`$1000-$2FFF`、作業領域は`$3000-$4FFF`です。

## 開発

```sh
JRASM=/absolute/path/to/jrasm make build
RUNNER_BUNDLE=/absolute/path/to/emulator/bundle make run
```

`tests/model.py`は上流`rules.py`を写したPythonモデルで、`tests/expectations.json`のRAM期待値を計算します。
各面は、12本の行・列の反転の全4,096通りを調べた最少手順（`plan()`）で解いています。最少なので、最後の変更より前につながることはありません。
リプレイのキー間隔は、モデルが数えた演出のフレーム数から決めています。
