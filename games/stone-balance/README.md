# STONE BALANCE

3つの山から、交互に1〜3個の石を取るライバルとの対戦ゲームです。全10面で、1〜5面は
「最後の石を取った方が勝ち」、6〜10面は「最後の石を取った方が負け」です。JR100devの
`STONE BALANCE 2.0.0`（`games/stone_balance/rules.py`）を仕様として、JR-200向けにM6800アセンブリで
作り直しました。山の数、勝ち局面の表、ライバルの手の選び方は上流と同じです。

## 目的と勝敗

- 自分の番に、1つの山から1〜3個の石を取ります。複数の山から同時には取れません。
- ライバルは、自分が勝てる形を残す手を表から探して取ります。見つからなければ1個だけ取ります。
- 1〜5面（`LAST STONE WINS`）: 最後の石を取ればクリア、ライバルに取られると失敗です。
- 6〜10面（`LAST STONE LOSES`）: 最後の石を取ると失敗、ライバルに取らせればクリアです。
- 10面をクリアすると`ALL STAGES CLEAR - THANK YOU`で終わります。

## 操作

| key | 動作 |
| --- | --- |
| `W` / `S` | 山を選ぶ（上下で循環） |
| `A` / `D` | 取る数を1〜3で選ぶ（`A`で増やし、`D`で減らす。循環） |
| `RETURN` | 黄色の石を取る |
| `SPACE` | この面のやり直し確認。初期選択はNO、`A`/`D`で選び`RETURN`で確定 |
| `ESC` / `CTRL+C` | ゲームを終えてBASICへ戻る |

石が1個ずつ飛んでいく演出が終わってから次のキーを押してください。演出中のキーは捨てられます。

## 最初の目標と序盤のコツ

- 1面の山は2・3・7個です。最初の手で左の山の2個を取ると、ライバルに勝ち筋が残りません。
- 取った後の3つの山を、ライバルが番の時に「負けの形」にするのが基本です。
- 6面からは勝敗の条件が逆になります。画面上の`LAST STONE WINS`／`LOSES`の色（緑／赤）を確かめてください。

## 画面（色と記号）

| もの | 色 | 形 |
| --- | --- | --- |
| 石 | 白 | 丸い石 |
| 次に取る石 | 黄 | 下に`^` |
| 選んだ山の棚 | 黄 | 棚の縁、左端に`>` |
| ほかの棚 | 青 | 棚の縁 |
| 自分が取った石 | 黄 | 右下へ飛ぶ |
| ライバルが取った石 | 赤 | 右下へ飛ぶ |
| 勝敗の条件 | 緑（勝ち）／赤（負け） | 上の文字 |

## 音

| 場面 | 音 |
| --- | --- |
| タイトル | ヘ長調の3声の曲（音源F・D・Cを同時に使用、ループ） |
| 石を取る | 1個ごとのクリック（音源C） |
| ライバルの手の後 | 2音の効果音（音源C） |
| クリア | 3声のヘ長調アルペジオ |
| 失敗 | 3声の下がるヘ短調の音型 |

## 起動

1. CJRを通常の`MLOAD`で読み込みます。
2. BASICから`A=USR($1000)`を実行します。
3. 終了後はBASICへ戻り、画面・ユーザー文字・文字RAM・キー制御ポートは起動前の状態に戻り、3つの音源は止まります。

標準のRAM構成で、ロード先は`$1000-$2FFF`、作業領域は`$3000-$4FFF`です。

## 開発

```sh
JRASM=/absolute/path/to/jrasm make build
RUNNER_BUNDLE=/absolute/path/to/emulator/bundle make run
```

`tests/model.py`は上流`rules.py`を写したPythonモデルで、`tests/expectations.json`のRAM期待値を計算します。
上流の勝ち局面の表（通常・逆）は、全1,024局面で独立したゲーム木探索と一致することを試験しています。
