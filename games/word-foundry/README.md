# WORD FOUNDRY

3文字の英単語を1文字ずつ変えて、中継点（VIA）を通ってから目標（TARGET）へたどり着く
単語はしごのパズルです。全16面です。JR100devの`WORD FOUNDRY 2.0.0`（`games/word_foundry/rules.py`）を
仕様として、JR-200向けにM6800アセンブリで作り直しました。16語、面ごとの開始・中継・目標の単語、
最短手数（PAR）と手数の上限（PAR＋2）は上流と同じです。

## 目的と勝敗

- 盤の16語から、今の単語と1文字だけ違う単語を選んで置き換えます。2文字以上違う単語は選べません（ブザー）。
- VIAの単語を一度通ってからTARGETの単語になるとクリアです。先にTARGETに着いてもクリアになりません。
- 手数がPAR＋2に達するとはしごが尽きて失敗（`WORD LADDER RAN OUT OF STEPS`）です。`RETURN`でやり直し確認に進みます。
- 16面をクリアすると`ALL STAGES CLEAR - THANK YOU`で終わります。

## 操作

| key | 動作 |
| --- | --- |
| `W` / `A` / `S` / `D` | 盤の単語を選ぶ（端では止まる） |
| `RETURN` | 選んだ単語に置き換える |
| `SPACE` | この面のやり直し確認。初期選択はNO、`A`/`D`で選び`RETURN`で確定 |
| `ESC` / `CTRL+C` | ゲームを終えてBASICへ戻る |

置き換えの演出と、VIAに着いたときの光の演出が終わってから次のキーを押してください。演出中のキーは捨てられます。

## 最初の目標と序盤のコツ

- 1面はCATからCOT（VIA）を通ってPIGへ。PARは5手です（CAT→COT→COG→DOG→DIG→PIG）。
- 緑の背景と`*`が付いた単語が、次に選べる単語です。
- 先にVIAまでの道を、次にTARGETまでの道を考えると、手数を無駄にしません。

## 画面（色と記号）

| もの | 色 | 形 |
| --- | --- | --- |
| 今の単語（CURRENT） | 青い札に黄 | 上段の札 |
| 目標（TARGET） | 赤い札に白 | 上段右の札 |
| 中継点（VIA） | 紫の札に白 | 通ると右に`*` |
| 次に選べる単語 | 緑の背景に黒 | 右に`*` |
| 盤の今の単語 | 青の背景に黄 | 盤の中の同じ単語 |
| 置き換わる文字 | 黄 | 今の単語の下へ落ちてくる |
| 経路 | 水色 | 画面下に直近8語 |

## 音

| 場面 | 音 |
| --- | --- |
| タイトル | イ短調の3声の曲（音源F・D・Cを同時に使用、ループ） |
| 置き換え | 文字が動くたびのクリックと、置いたときの2音（音源C） |
| 選べない単語 | 低いブザー（音源C） |
| クリア | 3声のイ長調アルペジオ |
| 手数切れ | 3声の下がるイ短調の音型 |

## 起動

1. CJRを通常の`MLOAD`で読み込みます。
2. BASICから`A=USR($1000)`を実行します。
3. 終了後はBASICへ戻り、画面・ユーザー文字・文字RAM・キー制御ポートは起動前の状態に戻り、3つの音源は止まります。

標準のRAM構成で、ロード先は`$1000-$2FFF`、作業領域は`$3000-$4FFF`です。

## 開発

```sh
JRASM=/absolute/path/to/jrasm make build
RUNNER_BUNDLE=/absolute/path/to/emulator/bundle make run
```

`tests/model.py`は上流`rules.py`を写したPythonモデルで、`tests/expectations.json`のRAM期待値を計算します。
各面の解答は幅優先探索の最短経路で、長さが上流のPARと一致することを試験しています。
