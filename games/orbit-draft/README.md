# ORBIT DRAFT

2枚の候補から札を選んで4×4の盤に落とし、行・列を回して同じ札を3つ並べ、連鎖で得点を重ねて目標点を超えていく、終わりのないパズルです。
JR100devの`ORBIT DRAFT 3.0.1`（`games/orbit_draft/rules.py`）を仕様として、JR-200向けに
M6800アセンブリで作り直しました。札の出方（乱数）、落下、行と列の回転、3つ並びの判定と消去、落下による連鎖、
回転回数（SPINS）、得点と目標は上流と同じです。

## 目的と勝敗

- 右上の2枚（PICK）から1枚を選び、列を選んで落とします。札はその列のいちばん下の空きに入ります。
  使った側の候補にはNEXTの左端の札が入ります。
- 縦・横・斜めに同じ札が3つ並ぶと消え、上の札が落ちます。落ちた札がまた並ぶと連鎖（CHAIN）です。
  得点は「消えた枚数×2×連鎖数＋（同時に並んだ本数−1）×2」です。1回消すたびにSPINSが1増えます（最大4）。
- `ROW`は行を右へ1マス、`COL`は列を下へ1マス回します（端の札は反対側へ）。1回でSPINSを1使います。4枚が同じなら回りません。
- ラウンドの得点（GOAL左の数字）が目標に届くとクリアです。`RETURN`で次のラウンドへ進み、盤面と合計点はそのまま、目標は6上がります（最大60）。
- 盤が埋まり、SPINSも0になると失敗（`FULL BOARD - NO SPINS`）です。

札の並びは新しいゲームを始めるたびに変わります。上流はJR-100のタイマー（`entropy()`）を種にしますが、JR-200版はタイトル曲の再生位置を種にします。

## 操作

| key | 動作 |
| --- | --- |
| `A` / `D` | 候補の札を選ぶ。盤では列（`COL`）や落とす位置を選ぶ |
| `W` / `S` | 盤では行（`ROW`）を選ぶ。`S`で下のメニュー（CARD・ROW・COL）へ |
| `RETURN` | 候補の決定、札を落とす、行・列を回す、メニューの決定 |
| `SPACE` | 新しいゲームの確認。初期選択はNO、`A`/`D`で選び`RETURN`で確定（盤面と得点をリセット） |
| `ESC` / `CTRL+C` | ゲームを終えてBASICへ戻る |

`ROW`・`COL`は、メニューで`CARD`を選び直すまで続けて使えます。札が落ちる、回る、光って消える演出が終わってから次のキーを押してください。

## 最初の目標と序盤のコツ

- 下段には最初から4枚が並んでいます。同じ札を2枚並べた横に3枚目を落とすのが基本です。
- 消すとSPINSが増えます。回転で3つ並びを作ると、上の札が落ちて連鎖しやすくなります。
- NEXTを見て、次に来る札の置き場所を残しておきます。

## 起動

1. CJRを通常の`MLOAD`で読み込みます。
2. BASICから`A=USR($1000)`を実行します。
3. 終了後はBASICへ戻り、画面・ユーザー文字・文字RAM・キー制御ポートは起動前の状態に戻り、3つの音源は止まります。

標準のRAM構成で、ロード先は`$1000-$2FFF`、作業領域は`$3000-$4FFF`です。

## 開発

```sh
JRASM=/absolute/path/to/jrasm make build
RUNNER_BUNDLE=/absolute/path/to/emulator/bundle make run
```

`tests/model.py`は上流`rules.py`を写したPythonモデルで、`tests/expectations.json`のRAM期待値を計算します。
エミュレータから取るのは新しいゲームの開始時の種（`origin`、`$4720`に記録）だけで、ほかの値はすべてモデルの予測です。
上流は終わりのないゲームで、クリア後は盤面と得点を持ち越します。SDKの`port.inc`は各面の作業領域を消すため、上流の状態は`$4740`以降に別に置き、
直前のラウンドの次へ進んだときだけ持ち越します（それ以外は上流の`init()`と同じく最初から）。
手順は、モデル上で2手先まで読む貪欲な探索で求めています。
